**核心原则**
1. **境内站零业务**: 仅静态 HTML, 100% 符合 ICP / 公安备案 / 法规要求.
2. **境外站全业务**: 所有问卷、订单、支付、AI 调用都在 Vercel 境外, 走 Supabase.
3. **数据同步**: 单一 Supabase 实例, 两端无差别. 不需要双写或 ETL.
4. **登录归集**: 通过微信公众号 OAuth 拿到 openid → HTTP-only cookie → 订单 API 全部按 openid 过滤.

打开 Supabase Dashboard → SQL Editor, 执行 `supabase-schema.sql` 末尾的新增段:

```sql

ALTER TABLE orders
  ADD COLUMN IF NOT EXISTS openid TEXT;
CREATE INDEX IF NOT EXISTS idx_orders_openid ON orders(openid)
  WHERE openid IS NOT NULL;

-- 2. openid_bindings 表 (新建)
CREATE TABLE IF NOT EXISTS openid_bindings (
  openid TEXT PRIMARY KEY,
  unionid TEXT,
  nickname TEXT,
  bound_at TIMESTAMPTZ DEFAULT NOW(),
  last_seen TIMESTAMPTZ DEFAULT NOW()

-- 3. RLS 策略: orders 表只允许 openid 匹配的行可见
```

## 4. 数据流 / 同步机制

```
用户场景 A: 在 H5 完成支付
   浏览器 (微信内置 / 普通浏览器)
       │
       ▼
   h5.aiwill-planner.cn (Vercel)
       │ POST /api/create-order  (cookie: wx_openid=...)
       ▼
   Vercel Edge Function
       │ supabase.from('orders').insert({..., openid})
       ▼
   Supabase (Singapore)
       │
       │  ← 任何后续读取
       │
   GET /api/orders/[id]
       │ supabase ... WHERE openid = cookies.get('wx_openid')
       ▼
   返回用户的订单 (按 openid 隔离)

用户场景 B: 从 CN 静态站跳转到 H5
   浏览器 → aiwill-planner.cn (CN nginx, 仅静态 HTML)
       │
       │ <a href="https://h5.aiwill-planner.cn/questionnaire">
       │   开始问卷
       │ </a>
       ▼
   跳转到 Vercel 站, 触发微信 OAuth → 获取 openid → cookie 设置
```

**数据一致性保证**:
- Supabase 是 **唯一数据源**, 两端不做本地存储 (LocalStorage 仅缓存匿名问卷草稿).
- `orders.openid` 字段做软隔离: 用户登出后, 同设备换号也只能看到当前 openid 的订单.
- 微信公众号回调 (`/api/wechat/mp-callback`) 接收订阅事件, 写入 `wechat_subscribers`, 不直接写 `orders`.

## 6. (可选) 微信公众号 固定 IP 中继

### 6.1 问题背景
微信公众号 Open API (token / 客服消息 / menu 创建等) 要求 **服务器 IP 白名单**, 上限 50 个 IP. Vercel Edge Function 出口 IP 是动态的 (AWS us-east-1 NAT pool 数千个), 不可穷举, 因此无法直接调.

### 6.2 解决方案
HK CVM `43.129.207.154` 跑一个 nginx 反代:

```
Vercel Edge → http://43.129.207.154:443 → https://api.weixin.qq.com
                                          (固定出口 IP, 白名单只加 1 个)
```

### 6.3 部署
```bash
# 在 HK CVM 上:
sudo bash -c '
cat /Users/maran/aiwill-planner/deployment/hk-server/wechat-proxy.conf.snippet \
  >> /etc/nginx/conf.d/wechat-proxy.conf
nginx -t && nginx -s reload
curl -s --max-time 5 http://127.0.0.1:443/__proxy_health  # 期望: ok
'
```

### 6.4 Vercel 端配置
```env
WECHAT_PROXY_URL=http://43.129.207.154:443
```

代码侧已在 `src/lib/wechat/*` 中读取此环境变量, fallback 到 `https://api.weixin.qq.com`.

## 9. 故障排除 Runbook

| 现象 | 可能原因 | 处置 |
|---|---|---|
| H5 站打开 502 | Vercel 构建失败 / env 变量缺 | 看 Vercel Build Log → 修 env → 重 deploy |
| 主站 (CN) 打开空白 | nginx 配置错 / DNS 未生效 | `ssh root@124.222.215.107 'nginx -t && systemctl status nginx'`; 必要时 `deploy_mainland.sh` 回滚 |
| /api/* 在主站返回 404 (应 301) | nginx 配置被覆盖 | 重新 `bash deployment/mainland-server/deploy_mainland.sh` |
| 用户看不到自己的订单 | openid cookie 未设置 / RLS 策略错 | 排查 `wx_openid` cookie → 检查 RLS `orders_by_openid` 策略 |
| 微信公众号 menu 创建报 `40164 invalid ip` | IP 白名单未包含 `43.129.207.154` | mp.weixin.qq.com → 设置 → IP 白名单 → 添加 |
| AI 生成超时 | LLM_API_URL 慢 / 503 | Vercel Function logs 看 stack; 临时切到备用 LLM_API_URL_FALLBACK |
| 支付回调验签失败 | WECHAT_API_KEY 不一致 / 时钟漂移 | 比对商户后台 API 密钥; CVM 装 chrony 校时 |
