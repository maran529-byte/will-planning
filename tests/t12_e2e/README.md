# T12: 端到端（E2E）测试方案

## 1. 测试目标

覆盖对话 → AI生成 → 合同确认 → PDF下载 → 分享的完整用户流程，验证各模块间的集成正确性与数据一致性。

---

## 2. 测试范围

### 2.1 涉及模块
| 模块 | 职责 |
|------|------|
| t9-h5-frontend | H5 前端交互（用户对话、签署确认、分享） |
| t2-api-gateway | JWT 鉴权、路由、限流、熔断 |
| t4-contract-generator | AI 合同生成、合规校验、PDF 导出 |
| t1-compliance-engine | 合规规则引擎（字段验证、禁止词、金额限制） |

### 2.2 用户主流程
```
1. 登录/获取 Token
   → POST /api/v1/auth/login → JWT

2. 对话咨询（前端引导式问答）
   → 用户填写契约信息（名称、类型、签约方、条款）

3. AI 生成合同
   → POST /api/v1/contracts/generate
   → 合规引擎校验 → 返回合同内容

4. 合同确认/签署
   → POST /api/v1/contracts/:id/confirm
   → POST /api/v1/contracts/:id/sign

5. PDF 下载
   → GET /api/v1/contracts/:id/pdf

6. 分享
   → GET /api/v1/contracts/:id/share
   → 返回分享链接/二维码
```

## 3. 测试用例

### TC-E2E-001: 完整正向流程
**目的**: 验证从登录到分享的全链路正确性

**前置条件**:
- 所有后端服务正常运行
- 测试租户 `tenant-e2e` 已存在

**步骤**:
1. 登录获取 Token
2. 发起合同生成请求（完整必填字段）
3. 校验合同生成成功（status=200，返回 contract_id）
4. 确认合同
5. 签署合同（附签名数据）
6. 下载 PDF
7. 获取分享链接
8. 校验 PDF 文件非空且为 PDF 格式

**验收标准**:
- 步骤 1-7 均返回 `code: 0`
- PDF 文件大小 > 1KB
- 分享链接格式正确

**预期结果**: PASS

---

### TC-E2E-002: 合规校验拦截 — 合同金额超限
**目的**: 验证合同金额超限时 AI 生成被合规拦截

**步骤**:
1. 登录
2. 发起合同生成，金额字段填写 999999999（超限）
3. 验证被合规引擎 reject

**验收标准**:
- 返回合规错误（非 500）
- 错误信息包含金额限制相关提示

**预期结果**: PASS

---

### TC-E2E-003: 合规校验拦截 — 禁止词汇
**目的**: 验证合同内容包含禁止词汇时被拦截

**步骤**:
1. 登录
2. 发起合同生成，内容字段包含禁止词（来自 prohibited-terms.yaml）
3. 验证被合规引擎 reject

**验收标准**:
- 返回合规拒绝
- 禁止词被检测出

**预期结果**: PASS

---

### TC-E2E-004: JWT Token 失效
**目的**: 验证 Token 过期后请求被拒绝

**步骤**:
1. 登录获取 Token
2. 等待 Token 过期（或手动构造过期 Token）
3. 发起合同生成请求

**验收标准**:
- 返回 401 Unauthorized
- 错误信息为 "invalid token"

**预期结果**: PASS

---

### TC-E2E-005: 多租户数据隔离
**目的**: 验证租户 A 无法访问租户 B 的合同

**步骤**:
1. 租户 A 创建合同 CA-1
2. 租户 B 尝试访问 CA-1（通过 contract_id）
3. 验证访问被拒绝

**验收标准**:
- 租户 B 请求返回 403 或 404
- 租户 A 的合同数据不泄露

**预期结果**: PASS

---

### TC-E2E-006: 热更新规则后合同生成行为
**目的**: 验证运行时更新合规规则后，新规则立即生效且不影响已生成合同

**前置条件**: 合规规则支持热加载

**步骤**:
1. 登录
2. 使用旧规则生成合同（内容不含新禁止词）
3. 热更新禁止词列表，添加新词
4. 用新禁止词内容发起合同生成
5. 验证新规则生效（旧合同不受影响）

**验收标准**:
- 新规则立即生效
- 已生成合同不受热更新影响

**预期结果**: PASS

---

### TC-E2E-007: 并发签署同一合同
**目的**: 验证并发签署不会导致合同状态异常

**步骤**:
1. 登录
2. 确认合同 C
3. 并发发起 5 个签署请求到合同 C

**验收标准**:
- 仅 1 个请求成功（状态变为 signed）
- 其余请求返回错误（状态已变更）

**预期结果**: PASS

---

### TC-E2E-008: 熔断降级 — 合约生成服务不可用
**目的**: 验证下游服务不可用时网关正确熔断并返回友好错误

**步骤**:
1. 停止 t4-contract-generator 服务
2. 发起合同生成请求
3. 验证熔断触发，快速返回错误

**验收标准**:
- 响应时间 < 熔断阈值
- 返回 503 或 504

**预期结果**: PASS（需 t2-api-gateway 熔断组件）

---

### TC-E2E-009: 草稿保存与恢复
**目的**: 验证合同草稿保存后可以正确恢复

**步骤**:
1. 登录
2. 创建合同，填写部分字段，保存草稿
3. 获取合同列表，确认草稿存在
4. 获取草稿详情，验证字段一致

**验收标准**:
- 草稿保存成功
- 恢复后字段与保存时一致

**预期结果**: PASS

---

### TC-E2E-010: 合同签署后状态流转
**目的**: 验证合同状态从 draft → pending → signed 的正确流转

**步骤**:
1. 登录
2. 创建合同（draft）
3. 确认合同（pending）
4. 签署合同（signed）
5. 尝试再次签署

**验收标准**:
- 状态按序流转
- 已签署合同不可重复签署

**预期结果**: PASS

## 5. 测试执行方式

### 5.1 依赖服务
- t1-compliance-engine (端口 8080)
- t2-api-gateway (端口 8088)
- t4-contract-generator (端口 8081)

### 5.2 执行命令
```bash
# 方式一：直接运行
go test -v ./tests/t12_e2e/...

# 方式二：使用脚本
bash tests/t12_e2e/scripts/run.sh

# 方式三：带 Token 复用（减少登录次数）
go test -v -run TestE2E ./tests/t12_e2e/... -token-cache
```

### 5.3 环境变量
| 变量 | 说明 |
|------|------|
| E2E_GW_URL | API Gateway 地址（默认 http://localhost:8088） |
| E2E_TENANT | 测试租户 ID（默认 tenant-e2e） |
| E2E_USER | 测试用户手机号（默认 13800138000） |
| E2E_CODE | 验证码（默认 123456） |

## 6. 风险项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 后端服务未启动 | 测试无法执行 | 执行前检查服务健康状态 |
| 熔断组件未实现 | TC-E2E-008 跳过 | 标记为需增强项 |
| PDF 渲染依赖外部库 | 可能存在格式差异 | 使用文本 PDF 断言（大小/MIME） |
| 多租户隔离未严格验证 | TC-E2E-005 可能假阳性 | 需数据库层面验证 |
